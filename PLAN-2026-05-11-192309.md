# Brewsty improvement plan - 2026-05-11 19:23:09 +02:00

## Problem

Brewsty already has a working Rust/egui architecture and passing tests, but the audit found improvement opportunities across security, performance, UI, UX and maintainability. The goal is to implement all identified items as cohesive, reviewable changes and commit them in logical chunks.

## Approach

Work in phases ordered by risk and dependency:

1. Security hardening
   - Remove shell invocation from installed size calculation.
   - Validate local paths before opening service files/logs.
   - Add import and Brewfile input limits/validation.
   - Redact sensitive output before exposing logs.
   - Save configuration/history atomically with private permissions.
2. Performance improvements
   - Avoid sorting package lists on every frame.
   - Cache filtered visible rows for package tables.
   - Make package size loading less expensive or explicitly lazy.
   - Improve package-info loading with lower concurrency, cache and queue visibility.
   - Improve search responsiveness and stale-result handling.
3. UX improvements
   - Add cancellable sequential update flow with clearer progress.
   - Strengthen destructive confirmations with exact impact details.
   - Improve search, loading, empty and error states.
   - Keep Installed/Search state consistent after install, uninstall and update.
4. UI and design-system improvements
   - Extract reusable status/action/message/table helpers where practical.
   - Improve settings hierarchy and visual grouping.
   - Add compact/comfortable table density and clearer table affordances.
   - Reduce reliance on color-only status indicators and add tooltips/copy consistency.
5. Architecture and tests
   - Reduce `BrewstyApp` coupling by extracting focused state/helpers where feasible.
   - Improve async task tracking semantics for cancellation, deduplication and progress.
   - Add tests for security validation, import limits, file writes, task queue behavior and performance-sensitive state transitions.

## Commit strategy

Use repository convention with Conventional Commit style:

1. `docs: add timestamped improvement plan`
2. `fix(security): harden command and file boundaries`
3. `perf(ui): reduce package list frame work`
4. `feat(ux): improve long-running operation feedback`
5. `refactor(ui): extract shared presentation helpers`
6. `test: cover validation and task behavior`

Every commit will include:

```text
Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>
```

## Validation

After each major phase, run targeted checks when relevant. Before final handoff, run:

```bash
cargo fmt --check
cargo test --quiet
cargo clippy --quiet --all-targets --all-features -- -D warnings
```

## Notes

- Do not remove existing behavior unless it is unsafe or directly conflicts with the improvement goal.
- Prefer precise, small helpers over broad rewrites.
- Preserve current Homebrew command behavior while adding validation and safer defaults.
